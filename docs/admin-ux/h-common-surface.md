# 案 H: 共通の表層 設計

[現状構造の棚卸し](./current-structure.md) の案 H(2026-10-17 採用)を具体化する。案 A〜G の画面に共通する骨格・部品・文言・状態表示の決まりをまとめる。各案の設計書は、ここで決めた部品と決まりを使う前提で書かれている。

## 1. 目的

- 画面ごとに作りが異なる箇所(確認ダイアログ、見出しの階層、エラーの出し方など)を揃え、どの画面でも同じ操作が同じ場所・同じ見た目で行えるようにする
- 内部用語や生の値(ISO 形式の日時、`version`、英語のエラー文)を画面に出さない

## 2. ページの骨格

すべての画面を次の骨格で組む([案 A](./a-navigation.md) 5 章)。

```
┌──────────────────────────────────────────────────────┐
│ パンくず   ホーム › お知らせ › 編集                         │
│ 見出し(h1) お知らせを編集            [補助操作] [主操作]      │
│ ──────────────────────────────────────────────────── │
│ (切断時のみ)接続バナー                                   │
│ 本文                                                  │
└──────────────────────────────────────────────────────┘
```

- ページの見出しは必ず `h1` を 1 つだけ置く。現状のモジュール画面は `h2` で始まっており、これを揃える
- 主操作(新規追加、保存など)は見出しの右端に 1 つだけ置き、塗りのボタンにする。補助操作はその左に枠線のボタンで置く。編集画面の保存・公開は公開ボックス([案 C](./c-publish-box.md))に置くため例外とする
- 骨格は共通のレイアウト部品(例: `PageHeader`)として用意し、各画面はそれを使う

## 3. 共通部品

`packages/ui`(react-aria-components + StyleX)に次の部品を追加する。現在あるのは Button / TextField / TextArea / Checkbox / CheckboxGroup / Select / RichTextEditor のみ(`packages/ui/src/index.ts`)。

| 部品                                | 用途                                                     | 使う案     |
| ----------------------------------- | -------------------------------------------------------- | ---------- |
| モーダルダイアログ / 確認ダイアログ | 削除・取り下げなどの確認、メンバー追加、メディア選択     | C・D・F・G |
| トースト                            | 保存・公開・削除などの結果の通知                         | C・D・F・G |
| パンくず                            | 現在地の表示                                             | A          |
| メニュー                            | アカウントメニュー、テナント切替、一括操作、行アクション | A・D       |
| 表(選択・並べ替え付き)              | コンテンツ一覧、メディアのリスト表示、メンバー一覧       | D・F・G    |
| タブ                                | 一覧の公開状態の切り替え                                 | D          |
| 検索欄                              | 一覧・メディアの検索                                     | D・F       |
| ツールチップ                        | 相対時刻の日時表示、無効なボタンの理由                   | B・C・D    |
| ドロップ領域 / ファイル選択         | メディアのアップロード                                   | F          |
| 進捗表示                            | アップロード、一括操作の進捗                             | D・F       |
| バッジ                              | 公開状態・ステータスの表示                               | B・C・D    |
| 空状態                              | 「まだありません」と次の行動のボタン                     | A・B・D・F |
| スケルトン                          | 同期完了前・読み込み中の表示                             | B・D・F    |
| バナー                              | 接続の切断、画面全体に関わる警告                         | A・C       |
| 相対時刻                            | 「10 分前」の表示とツールチップの日時                    | B・D・F    |

- react-aria-components が持つ部品(Dialog / Modal / Breadcrumbs / Menu / Table / Tabs / SearchField / Tooltip / DropZone / FileTrigger / ProgressBar など)を土台にし、見た目だけを StyleX で揃える。キーボード操作とスクリーンリーダー対応を部品側で担保するため
- トーストは react-aria-components で安定版になっていない可能性がある(推測)。実装時に採否を確認し、使えなければ自前で作る

## 4. 文言

### 4.1 用語の対応表

画面に出す言葉は次の表を唯一の基準とし、管理画面の中に 1 か所(例: `lib/labels.ts`)で定義する。現在は `STATUS_LABELS` が一覧画面とステータス切替で別々に定義されている(`routes/t/$tenantSlug/records/$typeKey/index.tsx` と `components/status-control.tsx`)。

| 内部の値                                   | 画面の表示                                      |
| ------------------------------------------ | ----------------------------------------------- |
| record                                     | (型名で呼ぶ。総称が要る場合は「コンテンツ」)    |
| content type                               | コンテンツタイプ                                |
| asset                                      | メディア                                        |
| module                                     | モジュール                                      |
| tenant                                     | サイト                                          |
| owner / editor / viewer                    | 管理者 / 編集者 / 閲覧者                        |
| draft / in_review / ready / archived       | 下書き / レビュー中 / 公開準備完了 / アーカイブ |
| 公開版あり / 公開後の編集あり / 公開版なし | 公開中 / 未反映の変更あり / 未公開              |
| field key                                  | API で使う名前                                  |

「テナント」は運営者と開発者の言葉のため、利用者の画面では「サイト」と呼ぶ(サイト名、サイトの識別子、サイト切替)。

### 4.2 書き方

- 文体は「です・ます」。ボタンは動詞で短く(「保存」「公開」「削除する」)
- 確認ダイアログのボタンは「OK」ではなく、実行する操作名にする(「削除する」「公開を取り下げる」)
- エラーは「何が起きたか」と「どうすればよいか」を書く(例: 「公開できませんでした。接続を確認して、もう一度お試しください」)
- API のエラー文をそのまま表示しない。現在の公開ボタンは例外の `message` をそのまま表示している(`components/publish-toolbar.tsx`)。エラーコードから利用者向けの文に置き換える対応表を作り、該当が無いときは汎用の文にする

## 5. 日時の表記

- 7 日以内は相対表記(「たった今」「10 分前」「3 時間前」「昨日」「3 日前」)、それより前は「2026/10/17 10:00」
- 相対表記にはツールチップで日時を添える
- タイムゾーンと書式はブラウザの設定に従う(`Intl.DateTimeFormat`、`Intl.RelativeTimeFormat` を使う)
- 現在 ISO 形式のまま表示している箇所(一覧の更新日時、公開状態パネルの公開日時)はすべて置き換える

## 6. 状態の表示

| 状態                   | 表示                                                                                                                                                                 |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 同期完了前・読み込み中 | スケルトン。現在の「同期中…(状態: connecting)」の 1 行表示はやめる                                                                                                   |
| 空                     | 空状態の部品で、説明と次の行動のボタン(例: 「お知らせはまだありません」[お知らせを追加])                                                                             |
| 接続の切断             | シェルに 1 か所だけバナーを出す(全画面共通)。現在は画面ごとに `ConnectionBanner` を置いている。サイドバー下部の同期状態も警告色にする([案 A](./a-navigation.md) 3.3) |
| 画面全体のエラー       | 既存の `ErrorScreen` を使い、再読み込みとホームへ戻るボタンを置く                                                                                                    |
| 操作の失敗             | トースト(エラー色)。入力内容の問題はフィールドの下に表示する                                                                                                         |

## 7. 権限による出し分け

- 権限の判定は 1 つのフックにまとめる(例: `useCan("record:publish")`)。対応表は API の `apps/api/src/auth/permissions.ts` と同じものを管理画面側に持つ(共有パッケージに移すかは実装時に決める)。現在は `tenant.role !== "viewer"` の比較が公開ボタンとステータス切替に個別に書かれている
- **隠す**: そのロールでは常に使えない機能(viewer の新規追加、editor 以下の設定)
- **無効にして理由を添える**: 状況によって使えない操作(切断中の公開など)。ツールチップで理由を出す
- API 側の権限判定は今のまま残す。画面の出し分けは誤操作を減らすためのもので、守りは API が担う

## 8. 確認の使い分け

| 操作                                                                                                           | 確認                               |
| -------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| 元に戻せない、または公開中の内容に影響する操作(削除、公開の取り下げ、メンバーを外す、公開したままのアーカイブ) | 確認ダイアログ。実行ボタンは危険色 |
| それ以外(保存、公開、ステータスの変更)                                                                         | 確認なし。結果をトーストで知らせる |

- 現在の確認は、ボタンが「削除を確定」に切り替わるインライン型(コンテンツの削除)と、ページ内に出る `alertdialog` の div(メディアの削除)が混在している。すべて確認ダイアログの部品に揃える

## 9. デザイントークン

見た目の値は「プリミティブトークン < セマンティックトークン < テーマ」の 3 層で管理する(2026-10-17 決定)。部品と画面はセマンティックトークンだけを使う。詳細は [デザイントークン 設計](./h-design-tokens.md) にまとめる。

## 10. 画面幅への対応

- 幅 960px 未満: サイドバーを畳み、上部の細いバーから開く([案 A](./a-navigation.md) 3.4)
- 編集画面: 幅が狭いときは公開ボックスをフォームの後ろに回し、主ボタンを画面下部に固定する([案 C](./c-publish-box.md) 2 章)
- 表: 幅が狭いときは優先度の低い列(ステータス、更新日時など)を隠す

## 11. アクセシビリティ

- サイドバーの現在地に `aria-current="page"` を付ける([案 A](./a-navigation.md))
- モーダルを開いたらモーダル内にフォーカスを移し、閉じたら開いたボタンへ戻す(react-aria-components の標準の挙動)
- トーストは `role="status"` で読み上げる。エラーのトーストは `role="alert"`
- 色だけで状態を伝えない。公開状態のバッジは文字も併記する
