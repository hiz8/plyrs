# 案 B: ホーム 設計

[現状構造の棚卸し](./current-structure.md) の案 B(2026-10-17 採用)を具体化する。対象はテナントの着地点 `/t/:slug/`(現在は型定義一覧へのリダイレクトのみ)。サイドバー上の位置と呼称の扱いは [案 A](./a-navigation.md) に従う。

## 1. 目的と名称

ログイン直後に、利用者が次の作業へすぐ移れる起点を用意する。WordPress のダッシュボードのうち、利用者がよく使う「アクティビティ(最近の投稿)」「クイックドラフト」「下書き」に相当する部分を取り入れる。

名称は「ホーム」を提案する。置く要素は 2 章のとおり作業の起点(最近の更新、自分の下書き、新規追加の入口)が中心で、アクセス解析のような数値やグラフは置かない。「ダッシュボード」は数値を並べる画面を連想させやすく、中身とずれるため。

## 2. 画面構成

```
┌──────────────────────────────────────────────────────────────┐
│ ホーム                                                        │
│                                                              │
│ 新規追加  [お知らせ] [ブログ] [イベント]                         │  ← 2.1
│                                                              │
│ ┌─ 自分の下書き ──────────────┐ ┌─ 確認待ち ────────────────┐ │
│ │ 秋のキャンペーン  お知らせ  3 時間前│ │ レビュー中      2 件 ›    │ │  ← 2.2 / 2.3
│ │ 新メニューの紹介  ブログ    昨日   │ │ 公開準備完了    1 件 ›    │ │
│ │ すべて見る ›               │ └──────────────────────┘ │
│ └──────────────────────────┘                              │
│                                                              │
│ ┌─ 最近の更新 ─────────────────────────────────────────────┐ │
│ │ 年末年始の営業について   お知らせ   下書き   10 分前           │ │  ← 2.4
│ │ 10/20 ワークショップ     イベント   下書き   2 時間前          │ │
│ │ …                                                        │ │
│ └──────────────────────────────────────────────────────────┘ │
│                                                              │
│ ┌─ 予約: 今日の予約 ──────────┐ ┌─ (他のウィジェット) ────────┐ │  ← 2.5
│ │ 10:00 田中 様 ・ カット  確定  │ │                          │ │
│ └──────────────────────────┘ └──────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

枠の配置(D3 で確定、2026-10-18): 上から「新規追加」の行 → 2 列(自分の下書き / 確認待ち)→ 全幅(最近の更新)→ モジュールのウィジェットの 2 列グリッド。各枠は `bg.surface` のカード(`radius.container`)で、題は 14px 600、行は 40px で罫線区切り。見出しの右にはメールアドレスと役割を添える。読み込み中は枠の見出しを残して中身だけスケルトンにし、0 件の枠は見出しを残してアイコン + 1 行の文(「下書きはありません」「確認待ちのコンテンツはありません」)を置く。

(2026-10-20、V4-B)見出しの右の補足は、管理者・編集者が「{email} ・ {役割}」、閲覧者が錠アイコン +「閲覧のみ ・ {email}」(一覧・編集画面の `meta` と揃える)。自分の情報が未取得のときは役割だけ(閲覧者は「閲覧のみ」だけ)(B6)。枠の中の 0 件表示は ui の `EmptyState`(破線の枠)を使わず、枠内の小さな表示(アイコン 20px・線幅 1.75 + 1 行の文 + 任意の 1 行の案内)にして破線の二重枠を避ける。画面全体の空状態(型 0 件の編集者・閲覧者)は `EmptyState` を使う(B8)。読み込み中は h1「ホーム」を出したまま、各枠の見出しを残して中身だけスケルトンにし、本文の入れ物に `aria-busy` を付ける(B12)。

### 2.1 新規追加

- サイドバーに出しているコンテンツの型(案 A 3.2 の「コンテンツ」とモジュールの型)ごとに「新規追加」ボタンを並べる。押すとその型の作成画面へ移る
- 並び順はサイドバーと同じにする
- viewer には表示しない
- (2026-10-20、V4-B)ホームが扱う型は `sidebarContentTypes(types)`(利用者の型、`menuOrder` 順)に続けて `moduleNavGroups(modules, types)` の型。メディア(`asset`)とモジュールの内部用の型は含まない。両群の間に区切り線を入れる(B14)
- (2026-10-20、V4-B)「新規追加」の行は枠線のボタン(`Button variant="secondary" icon={Plus}`、押すと作成画面へ `navigate`)。行の先頭の「新規追加」は見出しではなくラベル(`span`)(B20)

### 2.2 自分の下書き

- ステータスが「下書き」で、最後に自分が編集したものを、更新日時の新しい順に 5 件まで表示する。各行は編集画面へのリンク
- 「下書きをすべて見る ›」を枠の最下部に置く(案 D の絞り込み済み一覧へ)
- (2026-10-20、V4-B)下書きの件数がある型が 1 つなら、その型の絞り込み済み一覧へのリンクにする。複数なら行はリンクにせず、行の下に「お知らせ 2 ・ ブログ 1」のように型ごとのリンクを並べる(B1)。一覧に「自分が編集した」の絞り込みが無いため、行き先はその型の下書きの一覧(`?status=draft`、全員分)(B11)
- 「自分が作成したもの」ではなく「最後に自分が編集したもの」で判定する。同期データのレコードは作成者を持たず、最終更新者(`updatedBy`)だけを持つため(`packages/sync-protocol/src/messages.ts` の `SyncRecord`)。表示上の見出しは「自分の下書き」とし、判定の違いは利用者にとってほぼ差が無いと考える
- viewer には表示しない

### 2.3 確認待ち

- ステータスが「レビュー中」と「公開準備完了」の件数を、型をまたいで集計して表示する
- 各行は、そのステータスで絞り込んだ一覧へのリンクにする。行はステータスのバッジ + 短い説明(「公開前に確認が必要なもの」)+ 件数(accent の角丸の数字)+ chevron-right(D3 で確定)
- 件数が 0 のときは「確認待ちのコンテンツはありません」と表示する
- (2026-10-20、V4-B)3 行目に「未反映の変更あり」を入れる。V3 で入った全型の公開状態の一括取得(`publicationsQueryOptions(adminApi, tenantId)`)で、公開中かつ `sourceVersion < version` のものを数える。リンク先は一覧のタブ `unpublished-changes`。取得に失敗したときはこの行だけにエラー文と再試行を出す(他の 2 行は同期データなので影響しない)(B2)
- (2026-10-20、V4-B)件数がある型が 1 つなら行全体がその型の絞り込み済み一覧へのリンク。複数なら行はリンクにせず、行の下に型ごとのリンクを並べる(B1)

### 2.4 最近の更新

- 型をまたいで、更新日時の新しい順に 10 件を表示する。列はタイトル・型名・ステータス・更新日時
- 対象はサイドバーに出している型に限る(メディアと、モジュールの内部用の型は除く)
- 更新日時は「10 分前」「昨日」のような相対表記にし、ホバーで日時を出す(案 H の日時表記に合わせる)
- 将来、最終更新者の名前を表示したい。現状はユーザー ID しか手元に無いため、名前の取得は案 G(メンバー管理)とあわせて検討する
- (2026-10-20、V4-B)0 件のときは他の枠と同じ形で「まだ更新はありません」(inbox)。アーカイブも更新として数え、削除済み(`deletedAt`)は除く。対象の型は 2.1 の B14 の規則に従う(B9)

### 2.5 モジュールのウィジェット

- 有効なモジュールが、ホームに枠(ウィジェット)を差し込めるようにする。例: 予約モジュールの「今日の予約」
- 新しいスロット `home:widget` を設ける(`packages/ui/src/slots.ts` に語彙を追加)。中身は既存の `record-editor:panel` と同じく、タイトルと描画部品を持つ
- WordPress のダッシュボードウィジェット(`wp_add_dashboard_widget`)に相当する
- ウィジェットは 2 列のグリッドに流し込む。モジュールは大きさを `size: "half"`(1 列)か `"full"`(2 列分)で宣言し、既定は half。表示順はモジュールの有効化順(D3 で確定)
- (2026-10-20、V4-B)表示順はスロットの契約どおり `order` 昇順・同順は `id` とする。モジュール API に有効化日時が無いため「有効化順」は採らない。`HomeWidgetContribution` に `size?: "half" | "full"`(既定 half)と `moduleId?: string` を足し、`moduleId` があるものはそのモジュールが有効なときだけ描く(B5)

### 2.6 はじめての利用(型が無いとき)

コンテンツタイプが 1 件も無い場合、2.1〜2.4 の代わりに案内を表示する。

- owner: 「はじめに」として、次の手順をリンク付きで並べる
  1. コンテンツタイプを作成する(設定の型作成画面へ)
  2. メディアをアップロードする
  3. メンバーを招待する(案 G の実装後に表示)
  - (2026-10-20、V4-B)V4-B では手順 1 と 2 だけを出す。説明文に手順の数は書かず、V4-G の計画で手順 3 を足す(B4)
- editor / viewer: 「コンテンツの種類がまだありません。サイトの管理者に作成を依頼してください」。空状態の形で表示する
  - (2026-10-20、V4-B)管理者のメールアドレスは出さない(メンバー一覧 API は `member:manage` のみで、編集者・閲覧者は取れない)。文は「サイトの管理者に、コンテンツタイプの作成を依頼してください。作成されると、ここに新規追加の入口と最近の更新が表示されます」(B3)
- owner の「はじめに」は幅 760px のカードに番号付きの 3 手順を並べ、各行に行き先のボタンを置く。1 つ目が終わると普段の表示に変わる旨を書く(D3 で確定)

## 3. データの取得

- 2.1〜2.4 は、管理画面が同期で保持しているレコード(テナント接続時に全件を同期済み)から計算する。新しい API は不要
- 2.2 の「自分」を判定するため、ログイン中のユーザー ID が要る。現状の管理画面は自分のユーザー ID を保持していない(ログイン API の応答には含まれるが、再読み込みで失われる)。テナント利用者向けに自分の情報(ユーザー ID とメールアドレス)を返す API を追加する。案 A のアカウントメニューに表示するメールアドレスにも同じ API を使う
- 同期が完了するまでは、各枠に読み込み中の表示(スケルトン)を出す。現在の「同期中…(状態: connecting)」の 1 行表示は使わない
- (2026-10-20、V4-B)自分の情報の取得に失敗したときは、「自分の下書き」の枠だけにエラー文(`errorMessage`)と「再試行」を出し、他の枠は描く(一覧の R20 と同じ形)。見出しの右の補足は役割だけになる(B7)
- (2026-10-20、V4-B)型 0 件の判定は、初回同期の完了に加え、モジュール一覧の取得完了(失敗も完了扱い)を待ってから行う(モジュールの型だけがあるサイトで「はじめに」が一瞬出ないように)。モジュール一覧の取得に失敗したら利用者の型だけでホームを描き、`moduleId` 付きのウィジェットは出さない(B13)

## 4. 入れなかった要素

- **未反映の変更があるもの**(公開後に編集されたもの): 公開状態はレコードごとの API でしか取れず、一覧で集計する手段が無い。[案 D](./d-content-list.md) の 9 章で追加する公開状態の一括取得 API ができた後に、2.3 の確認待ちへ加える(V4-B で 2.3 に加えた)
- **アクセス解析・公開 API の利用量**: plyrs は公開側の表示を持たないため、意味のある数値を出せない
- **お知らせ・ニュース**(WordPress の「WordPress イベントとニュース」): 運営からの連絡手段は今回の範囲外とする

## 5. 権限による出し分け

| 要素                     | owner                  | editor     | viewer     |
| ------------------------ | ---------------------- | ---------- | ---------- |
| 新規追加                 | 表示                   | 表示       | 非表示     |
| 自分の下書き             | 表示                   | 表示       | 非表示     |
| 確認待ち                 | 表示                   | 表示       | 表示       |
| 最近の更新               | 表示                   | 表示       | 表示       |
| モジュールのウィジェット | モジュールの宣言に従う | 同左       | 同左       |
| はじめての利用           | 手順を表示             | 依頼の案内 | 依頼の案内 |
