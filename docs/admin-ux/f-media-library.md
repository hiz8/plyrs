# 案 F: メディアライブラリ 設計

[現状構造の棚卸し](./current-structure.md) の案 F(2026-10-17 採用)を具体化する。対象はメディアの一覧画面(現 `routes/t/$tenantSlug/assets/index.tsx`、[案 A](./a-navigation.md) の URL では `/t/:slug/media`)と、編集画面から開くメディア選択ダイアログ(現 `components/asset-picker.tsx`)。呼称は棚卸し 6.1 の決定に従い「メディア」とする(内部の型 `asset` は変えない)。

## 1. 目的

WordPress のメディアライブラリ(グリッド表示、ドラッグ&ドロップでのアップロード、詳細パネルでの代替テキスト編集)に慣れた利用者が、ファイルを探し、アップロードし、どこで使われているかを確認できるようにする。現状は表形式で一覧性が低く、アップロードは 1 ファイルずつの素の `<input type="file">`、編集は汎用のレコード編集画面に移ってしまう。

## 2. 現状の制約(設計の前提)

| 項目                   | 現状                                                                                                | 出典                                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 1 ファイルの上限       | 20 MB                                                                                               | `apps/api/src/routes/tenant.ts` の `MAX_ASSET_SIZE_BYTES` |
| 受け付ける形式         | 任意(画像の場合は幅・高さを自動取得)                                                                | 同上の `sniffImageSize`                                   |
| アップロード API       | 1 リクエスト 1 ファイル                                                                             | `POST /:tenantId/assets`                                  |
| ファイルの差し替え     | 不可(バイナリは不変、キーは `${tenantId}/${assetId}`)                                               | CLAUDE.md、design-spec §5                                 |
| 利用者が編集できる項目 | `alt`(代替テキスト)と `caption`(キャプション)のみ。ファイル名・形式・サイズ・幅・高さはシステム管理 | `packages/metamodel/src/asset-type.ts`                    |
| 公開                   | 参照元のコンテンツを公開すると一緒に公開される                                                      | `apps/api/src/do/publish.ts` の `publishRecordCore`       |
| 使用箇所               | 1 件ごとに取得できる(参照元の型・フィールド・ID・本文中かどうか)                                    | `GET /:tenantId/assets/:assetId/usage`                    |
| 未使用の一覧           | 取得できる                                                                                          | `GET /:tenantId/assets/orphans`                           |
| 管理画面でのプレビュー | 認証付きでファイル全体を取得して表示                                                                | `lib/asset-services.ts` の `resolveUrl`                   |

## 3. 画面構成

```
┌──────────────────────────────────────────────────────────────┐
│ ホーム › メディア                                               │
│ メディア                                      [ファイルを追加]    │
│                                                              │
│ [種類: すべて ▾] [使用状況: すべて ▾]  [🔍 ファイル名・代替テキスト] [▦][≡] │
│                                                              │
│ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐          │
│ │ 画像 │ │ 画像 │ │ PDF  │ │ 画像 │ │ 画像 │ │ 動画 │          │
│ └──────┘ └──────┘ └──────┘ └──────┘ └──────┘ └──────┘          │
│ ┌──────┐ ┌──────┐ ┌──────┐                                    │
│ │ …    │ │ …    │ │ …    │      (ここにファイルをドロップ)        │
│ └──────┘ └──────┘ └──────┘                                    │
└──────────────────────────────────────────────────────────────┘
```

### 3.1 表示の切り替え

- **グリッド表示**(既定): サムネイルを並べる。画像以外は形式のアイコンと拡張子を表示する(現行の `asset-thumb.tsx` の拡張子表示を引き継ぐ)
- **リスト表示**: 列はサムネイル・ファイル名・種類・サイズ・アップロード日時・使用状況。現在の表を整理したもの
- どちらの表示も、手元の同期データ(asset 型のレコード)を使う。表示の切り替えは利用者ごとにブラウザに記憶する

### 3.2 絞り込みと検索

- **種類**: すべて / 画像 / PDF / 動画 / 音声 / その他。`content_type` の先頭(`image/` など)で判定する
- **使用状況**: すべて / 未使用。「未使用」は、どのコンテンツからも使われていないファイル(現在の「未参照のみ表示」)。既存の未使用一覧 API を使う
- **検索**: ファイル名と代替テキストの部分一致
- 並び順はアップロード日時の新しい順を既定とし、ファイル名順にも切り替えられる
- 絞り込みの状態は URL のクエリに持たせる([案 D](./d-content-list.md) 8 章と同じ)

### 3.3 アップロード

- 画面のどこにでもファイルをドロップするとアップロードする。「ファイルを追加」ボタンからも選べる
- 複数のファイルを一度に選べる。API は 1 ファイルずつなので、管理画面が順に送る
- 20 MB を超えるファイルは、送る前に管理画面で弾き、「20 MB を超えるファイルはアップロードできません」と表示する
- アップロード中のファイルはグリッドの先頭に進捗付きで仮表示し、完了したら通常の表示に置き換える。失敗したものは失敗の表示と再試行ボタンを残す
- 複数ファイルのうち一部が失敗した場合は、成功と失敗の件数を分けて知らせる

## 4. 詳細パネル

ファイルをクリックすると、画面右側に詳細パネルを開く。汎用のレコード編集画面には移らない。URL は `/t/:slug/media/:assetId` とし、詳細を開いた状態を共有・再読み込みできるようにする。

```
┌─ 詳細 ─────────────────────────────┐
│ [プレビュー(画像・PDF・動画)]          │
│                                     │
│ ファイル名   autumn-campaign.jpg      │
│ 種類        image/jpeg               │
│ サイズ      1.2 MB                   │
│ 大きさ      1920 × 1080              │
│ アップロード 2026/10/17 10:00          │
│                                     │
│ 代替テキスト [秋のキャンペーンのバナー  ]   │
│ キャプション [                    ]   │
│                          [保存]      │
│                                     │
│ 公開状態    公開中                     │
│ 公開 URL    https://…/assets/…  [コピー]│
│                                     │
│ 使用箇所(2 件)                       │
│  ・秋のキャンペーン(お知らせ / アイキャッチ)›│
│  ・10 月の営業案内(お知らせ / 本文中)   › │
│                                     │
│ ファイルを削除                         │
└─────────────────────────────────────┘
```

- **ファイルの情報**: システム管理の項目は表示のみとする
- **代替テキストとキャプション**: ここで編集して保存する(同期経路での書き込み)。代替テキストの入力欄には「画像の内容を短く説明します。読み上げソフトや画像が表示できないときに使われます」と補足を出す
- **公開状態と公開 URL**: 公開中なら公開配信の URL(`/public/v1/:tenantSlug/assets/:assetId`)とコピーボタンを表示する。未公開なら「このファイルを使っているコンテンツを公開すると、一緒に公開されます」と表示する。公開状態は [案 D](./d-content-list.md) 9 章の一括取得 API(`type=asset`)で取得する
- **使用箇所**: 参照元のコンテンツのタイトル・型名・フィールドの表示名(本文中なら「本文中」)を表示し、編集画面へのリンクにする。現在の「型 key / フィールド key — ID 先頭 8 文字」の表示はやめる。タイトルと表示名は手元の同期データと型定義([案 E](./e-content-type-design.md) の `titleField` と `label`)から引く
- **削除**: 4.1 のとおり

### 4.1 削除

- 詳細パネルの「ファイルを削除」、またはグリッドで複数選択して一括削除する
- 確認ダイアログで使用箇所の件数を示す。使われているファイルの場合は「2 件のコンテンツで使われています。削除すると、そのコンテンツからこのファイルが表示されなくなります」と明示する
- 一括削除で使われているファイルが含まれる場合は、その件数を分けて示す

### 4.2 ファイルの差し替え

- ファイルは不変のため、差し替えはできない。詳細パネルには差し替えの操作を置かない
- 差し替えたい場合は、新しいファイルをアップロードして、使用箇所の各コンテンツで選び直す。使用箇所のリンクからたどれるようにすることで、この手順を補う

## 5. メディア選択ダイアログ

編集画面の「画像・ファイル」フィールドとリッチテキストの画像挿入から開くダイアログ(WordPress の「メディアを追加」に相当)。

- メディアライブラリのグリッド・絞り込み・検索・アップロードを同じ部品で使う
- ダイアログ内でのアップロードにも対応し、アップロードしたファイルをそのまま選択状態にする(現行の `asset-picker.tsx` の挙動を引き継ぐ)
- 選択したファイルの代替テキストを、ダイアログ内の詳細欄で編集できるようにする。挿入前に代替テキストを入れる流れを作るため
- 複数選択できるかは、フィールドの「1 件だけ / 複数」の設定に従う

## 6. 汎用の編集画面との関係

- asset 型のレコードは、汎用のコンテンツ編集画面では開かない。旧 URL(`/t/:slug/records/asset/:id` と、案 A の `/t/:slug/content/asset/:id`)は、詳細パネルを開いた状態のメディア画面(`/t/:slug/media/:assetId`)へリダイレクトする
- これにより、[案 C](./c-publish-box.md) 10 章で暫定とした「メディアの編集画面では公開関連の操作を外す」対応は、案 F の実装後に不要になる

## 7. 表示性能

- 現状の管理画面でのプレビューは、ファイル全体(最大 20 MB)を認証付きで取得している(`lib/asset-services.ts`)。グリッドに多数の画像を並べると、表示に時間がかかり通信量も増える
- 当面は、画面に入ったサムネイルだけを読み込む(遅延読み込み)ことと、取得済みの画像を再利用すること(現行のキャッシュを引き継ぐ)で対応する
- サムネイル用の縮小画像を返す仕組みは 9 章の未決事項とする

## 8. 権限

- viewer: 閲覧と詳細の表示のみ。アップロード・代替テキストの編集・削除は表示しない
- editor / owner: すべての操作ができる(アップロード前の役割検証は API 側で行われている)

## 9. 未決事項

- サムネイル用の縮小画像を返す API(Cloudflare の画像変換を使うか、アップロード時に縮小版を作るか)
- 「画像・ファイル」フィールドで受け付ける形式を絞れるようにするか(例: 画像のみ)。型定義への項目追加が必要で、[案 E](./e-content-type-design.md) の型設計とあわせて決める
- システム型 `asset` の型名(`ASSET_TYPE_DEFINITION.name` が「アセット」)を「メディア」に変えるか、画面側の表示だけで置き換えるか
