# 案 F: メディアライブラリ 設計

[現状構造の棚卸し](./current-structure.md) の案 F(2026-10-17 採用)を具体化する。対象はメディアの一覧画面(現 `routes/t/$tenantSlug/assets/index.tsx`、[案 A](./a-navigation.md) の URL では `/t/:slug/media`)と、編集画面から開くメディア選択ダイアログ(現 `components/asset-picker.tsx`)。呼称は棚卸し 6.1 の決定に従い「メディア」とする(内部の型 `asset` は変えない)。

## 1. 目的

WordPress のメディアライブラリ(グリッド表示、ドラッグ&ドロップでのアップロード、詳細パネルでの代替テキスト編集)に慣れた利用者が、ファイルを探し、アップロードし、どこで使われているかを確認できるようにする。現状は表形式で一覧性が低く、アップロードは 1 ファイルずつの素の `<input type="file">`、編集は汎用のレコード編集画面に移ってしまう。

## 2. 現状の制約(設計の前提)

| 項目                   | 現状                                                                                                | 出典                                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 1 ファイルの上限       | 20 MB                                                                                               | `apps/api/src/routes/tenant.ts` の `MAX_ASSET_SIZE_BYTES` |
| 受け付ける形式         | 任意(画像の場合は幅・高さを自動取得)                                                                | 同上の `sniffImageSize`                                   |
| アップロード API       | 1 リクエスト 1 ファイル                                                                             | `POST /:tenantId/assets`                                  |
| ファイルの差し替え     | 不可(バイナリは不変、キーは `${tenantId}/${assetId}`)                                               | CLAUDE.md、design-spec §5                                 |
| 利用者が編集できる項目 | `alt`(代替テキスト)と `caption`(キャプション)のみ。ファイル名・形式・サイズ・幅・高さはシステム管理 | `packages/metamodel/src/asset-type.ts`                    |
| 公開                   | 参照元のコンテンツを公開すると一緒に公開される                                                      | `apps/api/src/do/publish.ts` の `publishRecordCore`       |
| 使用箇所               | 1 件ごとに取得できる(参照元の型・フィールド・ID・本文中かどうか)                                    | `GET /:tenantId/assets/:assetId/usage`                    |
| 未使用の一覧           | 取得できる                                                                                          | `GET /:tenantId/assets/orphans`                           |
| 管理画面でのプレビュー | 認証付きでファイル全体を取得して表示                                                                | `lib/asset-services.ts` の `resolveUrl`                   |

### 3.1 表示の切り替え

- **グリッド表示**(既定): 160px の正方形のサムネイルを 12px 間隔で並べ、下にファイル名(11px、等幅)。画像以外はファイルのアイコンと拡張子のタグ(現行の `asset-thumb.tsx` の拡張子表示を引き継ぐ)。左上にチェックボックス、未使用のファイルには右上に警告色の「未使用」(D3 で確定、2026-10-18)
- **リスト表示**: 列はサムネイル(40px)・ファイル名(下に代替テキスト。未設定なら薄く「代替テキストなし」)・種類・サイズ・アップロード日時・使用状況(「2 件で使用」は成功色、「未使用」は警告色)。現在の表を整理したもの
- 絞り込みの行の右端に、グリッド / リストの切り替え(pill の 2 ボタン)と件数を置く
- どちらの表示も、手元の同期データ(asset 型のレコード)を使う。表示の切り替えは利用者ごとにブラウザに記憶する
- (2026-10-21、V4-F) 表示の切り替えの記憶は `localStorage` のキー `plyrs.media.view`(値 `grid` | `list`、既定 `grid`、サイト共通。`lib/theme.ts` と同じ様式。URL には載せない。F2)。未使用一覧 API は画面を開いている間は常に取得し(グリッドの「未使用」バッジとリストの使用状況の列に要る。F7)、リストの使用状況は「使用中」/「未使用」の 2 値で件数は出さない(件数は詳細パネルで出す)。グリッドは ui の `TileGrid`(RAC GridList layout="grid"、F17)、リストは ui `Table`(列と挙動は F20。並べ替えは列見出しではなく絞り込み行の「並び順」)。絞り込みの行は左から種類・使用状況・並び順の `Select`、`SearchField`、右端に件数と文字付きの `SegmentedControl`(アイコンだけの pill より a11y を優先。F21)。「新しい順」の鍵はアップロード日時で、asset の ID(UUIDv7)の時刻部から得る(`updatedAt` は代替テキストの保存で動くため使わない。F23)。ファイル名順は数字を数として比べる自然順(`Intl.Collator("ja", { numeric: true })`)の昇順、同点は ID 降順(F23、2026-10-24 の裁定)。一覧のデータは asset 型の同期データ(`deletedAt === null` のみ)で、同期前は読み込み表示(F34)。幅 960px 未満はメディアクエリだけで切り替え、グリッドのタイルが伸び、絞り込みの行は折り返し、リストは種類・サイズ・アップロードの列を隠し、見出しの主操作は「ファイルを追加」のまま(F33)

### 3.2 絞り込みと検索

- **種類**: すべて / 画像 / PDF / 動画 / 音声 / その他。`content_type` の先頭(`image/` など)で判定する
- **使用状況**: すべて / 未使用。「未使用」は、どのコンテンツからも使われていないファイル(現在の「未参照のみ表示」)。既存の未使用一覧 API を使う
- **検索**: ファイル名と代替テキストの部分一致
- 並び順はアップロード日時の新しい順を既定とし、ファイル名順にも切り替えられる
- 絞り込みの状態は URL のクエリに持たせる([案 D](./d-content-list.md) 8 章と同じ)
- (2026-10-21、V4-F) URL のクエリは `kind`(image | pdf | video | audio | other)・`usage`(unused)・`q`・`sort`(name。既定の新しい順は省く)で、`parseMediaQuery` / `toMediaSearch` が既定値を省く(`content-list.ts` と同じ規則。ページ送りは無く全件を描く。F6)。種類の判定は `mediaKindOf(contentType)`(`image/*`、`application/pdf`、`video/*`、`audio/*`、他。表示名は 画像 / PDF / 動画 / 音声 / その他。F19)。検索は大文字小文字を無視する部分一致で、`q` の正規化は `content-list.ts` の `searchText` と同じ(F22)

### 3.3 アップロード

- 画面のどこにでもファイルをドロップするとアップロードする。「ファイルを追加」ボタンからも選べる。ドラッグが本文に入ったら本文全体に accent.surface の暗幕と点線枠を重ね、「ここに置くとアップロードします」とファイル数を示す。グリッドの最下部には常時、薄いドロップ領域の案内を置く。0 件のときは本文全体を大きなドロップ領域にする
- 複数のファイルを一度に選べる。API は 1 ファイルずつなので、管理画面が順に送る
- 20 MB を超えるファイルは、送る前に管理画面で弾き、「20 MB を超えるファイルはアップロードできません」と表示する
- アップロード中のファイルはグリッドの先頭に進捗付きで仮表示(進捗率とバー / 順番待ち / 失敗)し、完了したら「完了」の印を数秒出してから通常の表示に置き換える。失敗したものは失敗の表示と再試行ボタンを残す。20 MB 超えのタイルには理由と「取り除く」。グリッドの上に全体の進捗(「2 / 5 件が完了」)と「残りを中止」のバーを出す(D3 で確定)
- 複数ファイルのうち一部が失敗した場合は、成功と失敗の件数を分けて知らせる
- (2026-10-21、V4-F) ファイルごとの進捗は `fetch` では取れないため、送信中は不確定の表示(`Spinner` + 「送信しています…」)とし、全体の進捗を件数(「2 / 5 件が完了」)の `ProgressBar` で示す(F9)。`useUploads()` が仮タイル(`UploadEntry`)の状態を持ち、完了は 3 秒残してから消し(その間は実レコードを重複して出さない)、失敗は「再試行」、送る前に弾いた失敗は理由と「取り除く」、「残りを中止」は `AbortController`(F10)。完了の印は一覧では仮タイルに 3 秒「完了」、選択ダイアログでは実タイルに「アップロード完了」(F40)。0 件(絞り込み無し)は ui の `DropZone isFill` が本文全体に広がる空状態で、viewer は `EmptyState`(F16)。画面全体のドロップは ui の `FileDropTarget`(暗幕 + 点線枠。F35)、ファイル選択は ui の `FileButton`(RAC FileTrigger。F39)。グリッド最下部の常時の案内は点線の帯(→ 2026-10-24 の持ち越しで XHR 化。K6)
- (2026-10-24、持ち越し)F9 は XHR 化すると決めた(持ち越しの計画 Task 7 で実装): ファイルごとの進捗は XHR(`upload.onprogress`)で取り、仮タイルにD3 M6 どおりに % とバイト数(「64% ・ 1.2 / 1.9 MB」)の `ProgressBar` を出す(進捗が無い間は従来の `Spinner`)。全体の進捗は件数(「2 / 5 件が完了」)のまま(K6)

## 4. 詳細パネル

ファイルをクリックすると、画面右側に詳細パネルを開く。汎用のレコード編集画面には移らない。URL は `/t/:slug/media/:assetId` とし、詳細を開いた状態を共有・再読み込みできるようにする。

```
┌─ 詳細 ─────────────────────────────┐
│ [プレビュー(画像・PDF・動画)]          │
│                                     │
│ ファイル名   autumn-campaign.jpg      │
│ 種類        image/jpeg               │
│ サイズ      1.2 MB                   │
│ 大きさ      1920 × 1080              │
│ アップロード 2026/10/17 10:00          │
│                                     │
│ 代替テキスト [秋のキャンペーンのバナー  ]   │
│ キャプション [                    ]   │
│                          [保存]      │
│                                     │
│ 公開状態    公開中                     │
│ 公開 URL    https://…/assets/…  [コピー]│
│                                     │
│ 使用箇所(2 件)                       │
│  ・秋のキャンペーン(お知らせ / アイキャッチ)›│
│  ・10 月の営業案内(お知らせ / 本文中)   › │
│                                     │
│ ファイルを削除                         │
└─────────────────────────────────────┘
```

- パネルは幅 360px で本文の右端に固定し、グリッドは残りの幅で列数が減る(1440px では 6 列 → 4 列)。上から プレビュー(高さ 200px、右下に大きさ)→ 情報 → 代替テキストとキャプション → 公開 → 使用箇所 → 削除。閉じるボタンと Esc で閉じる。狭い画面では下から出るシート(D3 で確定)
- **ファイルの情報**: システム管理の項目は表示のみとする
- **代替テキストとキャプション**: ここで編集して保存する(同期経路での書き込み)。代替テキストの入力欄には「画像の内容を短く説明します。読み上げソフトや画像が表示できないときに使われます」と補足を出す
- **公開状態と公開 URL**: 公開中なら公開配信の URL(`/public/v1/:tenantSlug/assets/:assetId`)とコピーボタンを表示する。未公開なら「このファイルを使っているコンテンツを公開すると、一緒に公開されます」と表示する。公開状態は [案 D](./d-content-list.md) 9 章の一括取得 API(`type=asset`)で取得する
- **使用箇所**: 参照元のコンテンツのタイトル・型名・フィールドの表示名(本文中なら「本文中」)を表示し、編集画面へのリンクにする。現在の「型 key / フィールド key — ID 先頭 8 文字」の表示はやめる。タイトルと表示名は手元の同期データと型定義([案 E](./e-content-type-design.md) の `titleField` と `label`)から引く
- **削除**: 4.1 のとおり
- (2026-10-21、V4-F) 詳細パネルは V4-E の `SidePanel` に `width`(360)と `narrowLayout="sheet"`(狭い画面で下から出る高さ 520px のシート)を足して使い、非モーダル・Esc・フォーカス復帰を共用する(F1)。ルートは `media/route.tsx`(レイアウト。`validateSearch` と `MediaLibrary`)・`media/index.tsx`・`media/$assetId.tsx`(component 無し)で、開閉は `navigate` で URL を変え、絞り込みの search は保つ(F5)。公開状態は `publicationsQueryOptions(…, "asset")` を開いたときに取得し、公開 URL は `publicAssetUrl(origin, slug, assetId)` で組む(F8)。代替テキストとキャプションは同期経路(`collection.update`)で保存し、「保存」は変更があるときだけ有効、viewer は読み取り専用(F13)。使用箇所は `assetUsageQueryOptions` + `resolveUsage` で、各行は RAC `Link`(型が手元に無ければリンクを出さない。F14)。パネルを開いている間は見出しと本文の右に 360px を空け、狭い画面は 0(F28)。閉じるボタン・Esc・別のタイルのクリックは `navigate` で、閉じたときは開いたタイルへフォーカスを戻す(F29)

### 4.1 削除

- 詳細パネルの「ファイルを削除」、またはグリッドで複数選択して一括削除する
- 確認ダイアログで使用箇所の件数を示す。使われているファイルの場合は警告色の注記で「2 件のコンテンツで使われています(秋のキャンペーン、10 月の営業案内)。削除すると、そのコンテンツからこのファイルが表示されなくなります。公開中のページでも表示されなくなります」と明示する(D3 で確定)
- グリッドで選択があるときは、絞り込みの行と表の間に一括操作のバー(案 D と同じ形)を出し、「削除」「N 件すべてを選択」「選択を解除」を置く
- 一括削除で使われているファイルが含まれる場合は、その件数を分けて示す
- (2026-10-21、V4-F) 削除は HTTP の `adminApi.deleteRecord`(一覧からの消滅はトゥームストーンの同期で反映)で、一括は `useBulkAction` を使い、バーはメディア用の `MediaBulkBar`(「削除」「N 件すべてを選択」「選択を解除」、実行中は進捗と「残りを中止」)。一括の「使われている件数」は選択のうち未使用一覧に無いもの(F11)。削除後は未使用一覧と公開状態を invalidate し、選択から外し、詳細パネルで開いていたファイルなら `/media` へ navigate する(F12)。確認の文言は題「{ファイル名} を削除しますか？」・「ファイルは元に戻せません。」・使用中なら警告の注記(タイトルは重複を除いた先頭 3 件、残りは「ほか {m} 件」)、使用箇所の取得中・失敗でも削除はできる(F37)

### 4.2 ファイルの差し替え

- ファイルは不変のため、差し替えはできない。詳細パネルには差し替えの操作を置かない
- 差し替えたい場合は、新しいファイルをアップロードして、使用箇所の各コンテンツで選び直す。使用箇所のリンクからたどれるようにすることで、この手順を補う

## 5. メディア選択ダイアログ

編集画面の「画像・ファイル」フィールドとリッチテキストの画像挿入から開くダイアログ(WordPress の「メディアを追加」に相当)。

- メディアライブラリのグリッド・絞り込み・検索・アップロードを同じ部品で使う
- ダイアログ内でのアップロードにも対応し、アップロードしたファイルをそのまま選択状態にする(現行の `asset-picker.tsx` の挙動を引き継ぐ)
- 選択したファイルの代替テキストを、ダイアログ内の詳細欄で編集できるようにする。挿入前に代替テキストを入れる流れを作るため
- 複数選択できるかは、フィールドの「1 件だけ / 複数」の設定に従う
- ダイアログの形(D3 で確定): 幅 1040px・高さ 720px。題「メディアを選択」の横にフィールド名と「1 件だけ / 複数選べます」、右上に「アップロード」。左に絞り込みと 140px のグリッド(複数なら左上のチェックボックスと右上の選択順の番号、1 件なら左上のラジオ)、右に幅 300px の「選択中」欄(サムネイル・ファイル名・大きさ・代替テキストの入力欄)。下部に「キャンセル」と「N 件を挿入」(1 件なら「このファイルを使う」)。ダイアログ内でアップロードしたファイルは「アップロード完了」の印付きで選択状態になり、代替テキストの入力欄にフォーカスが移る
- (2026-10-21、V4-F) ダイアログは `components/media/media-picker-dialog.tsx` の `MediaPickerDialog`(`ModalDialog size="xl"`、左に種類 `Select` + 検索 + `TileGrid size="sm"`、右に幅 300px の「選択中」欄、右上に `FileButton`「アップロード」。F15)。ダイアログ内のアップロードは同じ `useUploads` で、完了したファイルを選択に加え、代替テキストの入力欄にフォーカスを移す(F30)。`onSelect(items: PickedMedia[])` で、挿入時にダイアログで変えた代替テキストを同期経路で保存してから渡す(保存はサーバーの確定を待たずに挿入へ進み、失敗はトースト。「画像・ファイル」の複数は、ダイアログで確定した選択の順でフィールドの値を置き換える。リッチテキストの画像挿入は 1 件。F31、2026-10-24 の裁定で改定)。絞り込みの既定は `defaultKind` prop(画像挿入は `image`、「画像・ファイル」フィールドは `all`)で、並び順は新しい順固定、使用状況の絞り込みは出さない(F32)

## 6. 汎用の編集画面との関係

- asset 型のレコードは、汎用のコンテンツ編集画面では開かない。旧 URL(`/t/:slug/records/asset/:id` と、案 A の `/t/:slug/content/asset/:id`)は、詳細パネルを開いた状態のメディア画面(`/t/:slug/media/:assetId`)へリダイレクトする
- これにより、[案 C](./c-publish-box.md) 10 章で暫定とした「メディアの編集画面では公開関連の操作を外す」対応は、案 F の実装後に不要になる
- (2026-10-21、V4-F) `lib/legacy-redirect.ts` の `legacyPathname` を拡張し、`/t/:slug/content/asset`・`/content/asset/new` は `/t/:slug/media` へ、`/content/asset/:id`(旧 `/records/asset/:id` も)は `/t/:slug/media/:id` へ転送する。`lib/publish-box.ts` の `isAsset` / `kind: "asset"` と `components/publish-box.tsx` の分岐、`record-editor.tsx` の `isAsset` 渡しは整理して消す(`record-form.tsx` の `locked` は残す。F26)。asset 型は `sidebarContentTypes`(`source === "user"`)で既にサイドバーに出ない(F27)

## 7. 表示性能

- 現状の管理画面でのプレビューは、ファイル全体(最大 20 MB)を認証付きで取得している(`lib/asset-services.ts`)。グリッドに多数の画像を並べると、表示に時間がかかり通信量も増える
- 当面は、画面に入ったサムネイルだけを読み込む(遅延読み込み)ことと、取得済みの画像を再利用すること(現行のキャッシュを引き継ぐ)で対応する
- サムネイル用の縮小画像を返す仕組みは 9 章の未決事項とする
- (2026-10-21、V4-F) サムネイルは `components/media/media-thumb.tsx` の `MediaThumb` が `IntersectionObserver`(rootMargin 200px)で画面に入ってから `resolveUrl` を呼び(`IntersectionObserver` が無い環境は即時)、画像以外は種類のアイコン + 拡張子のタグを出す(F18)

## 8. 権限

- viewer: 閲覧と詳細の表示のみ。アップロード・代替テキストの編集・削除は表示しない
- editor / owner: すべての操作ができる(アップロード前の役割検証は API 側で行われている)
- (2026-10-21、V4-F) アップロードと代替テキスト・キャプションの編集は `record:write`、チェックボックス・一括操作・「ファイルを削除」は `record:delete` を `useCan()` で出し分ける。viewer は見出しの `meta` に「閲覧のみ」を出し、ドロップ(`FileDropTarget isDisabled`)と常時のドロップ案内も出さない。公開 URL のコピーと使用箇所のリンクは使える(F24)

## 9. 未決事項

- サムネイル用の縮小画像を返す API(Cloudflare の画像変換を使うか、アップロード時に縮小版を作るか)
- 「画像・ファイル」フィールドで受け付ける形式を絞れるようにするか(例: 画像のみ)。型定義への項目追加が必要で、[案 E](./e-content-type-design.md) の型設計とあわせて決める
- システム型 `asset` の型名(`ASSET_TYPE_DEFINITION.name` が「アセット」)を「メディア」に変えるか、画面側の表示だけで置き換えるか
