# 案 A: コンテンツ中心のナビゲーション 設計

[現状構造の棚卸し](./current-structure.md) の案 A(2026-10-17 採用)を具体化する。対象はテナント内の共通シェル(現 `routes/t/$tenantSlug/route.tsx`)のサイドバーと本文上部、およびテナント内の URL 構成。呼称は棚卸し 6.1 の決定に従う。

## 1. 目的

利用者がログイン後に「何かを書く・確認する場所」へ迷わず到達できるようにする。現状はサイドバーが「コンテンツタイプ」「アセット」「モジュール」の 3 項目で、コンテンツの一覧へは型定義一覧の行内リンクからしか入れない。WordPress の左メニュー(ダッシュボード、投稿、メディア、固定ページ、各カスタム投稿タイプ、…、設定)と同じく、コンテンツの種類ごとに入口を並べる。

## 2. 画面全体の構成

ヘッダーは設けず、サイト名・切替・同期状態・アカウントメニューもサイドバーに統合する(2026-10-17 決定)。縦の領域をすべて本文に使えるようにするため。

```
┌────────────────────────┬──────────────────────────────────────────┐
│ plyrs                  │ ホーム › お知らせ › 編集                    │ ← パンくず
│ サイト名 ▾              │                                          │
├────────────────────────┤ お知らせを編集                 [主操作]     │ ← 見出しと主操作
│ ホーム                  │                                          │
│                        │ (本文)                                    │
│ コンテンツ              │                                          │
│  お知らせ               │                                          │
│    一覧                 │                                          │
│    新規追加              │                                          │
│  ブログ                 │                                          │
│  イベント               │                                          │
│                        │                                          │
│ メディア                │                                          │
│                        │                                          │
│ 予約                   │                                          │
│  予約                  │                                          │
│  予約枠                 │                                          │
│  予約リソース            │                                          │
├────────────────────────┤                                          │
│ 設定                   │                                          │
│ ● 同期済み              │                                          │
│ [アカウント ▾]          │                                          │
└────────────────────────┴──────────────────────────────────────────┘
```

## 3. サイドバーの構成

サイドバーは上段・中段・下段の 3 段に分ける。上段と下段は固定し、中段だけをスクロールさせる。型やモジュールが増えても、サイトの切替とアカウントメニューが画面外に出ないようにするため。

### 3.1 上段: サイト名とサイト切替

- 「plyrs」の下にサイト名(テナント名)を表示する。画面上ではテナントを「サイト」と呼ぶ([案 H](./h-common-surface.md) 4.1)
- 所属テナントが複数あるときだけ「▾」を付け、クリックで切替メニューを開く。現在のヘッダーの「{テナント名}(テナント切替)」リンクは廃止する

### 3.2 中段: 主要な機能

利用頻度の高い順に「ホーム → コンテンツ → メディア → モジュール」と並べる(2026-10-17 決定)。WordPress の「ダッシュボード → 投稿 → メディア → 固定ページ…」と同じ並びにする。

#### ホーム

- テナントの着地点(`/t/:slug/`)。名称は「ホーム」を仮称とし、置く要素とあわせて案 B で最終決定する

#### コンテンツ

- 見出し「コンテンツ」(クリック不可)の下に、利用者が定義したコンテンツタイプ(`source: "user"`)を型の表示名で 1 項目ずつ並べる。データは同期済みの型定義(`useSyncTypes`)から作るため、型を追加・改名するとサイドバーにもすぐ反映される
- 項目をクリックするとその型の一覧へ移る。現在地の型だけ「一覧」「新規追加」の子項目を展開する(WordPress のカスタム投稿タイプのメニューと同じ)
- 並び順は当面、型の表示名の五十音順とする。利用者が並べ替えられるようにするには型定義に表示順を持たせる必要があり、案 E(型設計の改善)で扱う
- 型が多い場合(目安 10 件超)の折りたたみや検索は、実際の利用状況を見てから検討する

#### メディア

- 現在の「アセット」を「メディア」として独立の項目に置く。中身の作り直しは案 F で行う
- メディアは編集画面のメディア選択ダイアログから使う場面が多く、サイドバーから開く頻度はコンテンツより低い見込みのため、コンテンツの下に置く

#### モジュール

- 有効化されたモジュールごとに見出しを立て(例: 「予約」)、そのモジュールの型(`source: "plugin"`)を並べる。無効のモジュールは表示しない
- モジュールの型のうち、利用者が直接触らない内部用の型(例: 予約モジュールの「予約通知」は通知の二重配送を防ぐための型)は表示しない。そのため、モジュールの定義(manifest)に「サイドバーに出す型」を宣言する項目を追加する。宣言が無い型は表示する
- モジュールが独自の画面(design-spec §9.9 の `/modules/{id}/*`、例: 予約カレンダー)を持つ場合は、`nav:item` スロットでこの見出しの下に項目を足す(4 章)

### 3.3 下段: 設定・同期状態・アカウント

上から「設定 → 同期状態 → アカウントメニュー」の順に置く。

#### 設定

- owner にだけ表示する。API の権限上、型の設計(`type:manage`)とモジュールの有効化(`module:manage`)は owner のみに許可されている(`apps/api/src/auth/permissions.ts`)ため、editor と viewer には出しても操作できない
- 利用頻度が低く owner 専用のため、中段ではなく下段に置く
- クリックで設定のサブメニュー(または設定画面のトップ)を開く。中身は次のとおり
  - 「コンテンツタイプ」(型の設計)と「モジュール」: 現在のメインメニューから移す
  - 「一般」「メンバー」: 案 G で新設する。案 G の実装までは出さない

#### 同期状態

- 正常時は小さな点と「同期済み」の短い表示だけにする。現在のヘッダーの「同期: 同期済み」のテキストは廃止する
- 切断時は、この表示を警告色にするとともに、本文の上部に全画面共通のバナー(案 H)を出し、そこに「再接続」を置く。サイドバー下部の表示だけでは切断に気づきにくいため

#### アカウントメニュー

- サイドバーの最下部に置く。中身はメールアドレス、サイト切替、ログアウト。プロフィールとパスワード変更は案 G で足す

### 3.4 共通

- 現在地の項目をハイライトし、`aria-current="page"` を付ける。子画面(作成・編集)にいるときは親の型の項目をハイライトする
- 狭い画面ではサイドバーを畳む。ヘッダーは設けないが、サイドバーを開くボタンとサイト名だけを置く細いバーを画面上部に出す

## 4. スロット(`nav:item`)の変更

- コンテンツとモジュールの型の項目は、同期済みの型定義からコアが生成する。スロットには登録しない
- `nav:item` はモジュール独自の画面と、将来の追加画面のために残す。次の 2 点を拡張する
  - `group`: 項目を置く場所(`"module:<モジュール ID>"` / `"settings"` など)。指定が無ければ中段の最後に置く
  - `params`: `$tenantSlug` 以外のパスパラメータ。現状は `$tenantSlug` しか束縛できない制約がある(`packages/ui/src/slots.ts` の `NavItemContribution` のコメントで予告済み)
- コアの 3 項目(`core.content-types` / `core.assets` / `core.modules`)の登録は、上記の構成に合わせて置き換える

## 5. 本文上部(パンくず・見出し・主操作)

- **パンくず**: 本文の最上部に置き、「ホーム › お知らせ › 編集」のように現在地を示す。各段はリンク
- **見出しと主操作**: パンくずの下にページ見出しを置き、その右に画面の主操作ボタン(一覧なら「新規追加」など)を置く。位置は全画面で揃える(案 H)
- 編集画面の保存・公開は公開ボックス([案 C](./c-publish-box.md))に置くため、見出しの右には置かない

## 6. URL 構成

画面上の呼称に合わせて、テナント内の URL も改める。旧 URL は新 URL へリダイレクトし、ブックマークやリンクが切れないようにする。

| 画面                   | 現在の URL                            | 新しい URL                            |
| ---------------------- | ------------------------------------- | ------------------------------------- |
| ホーム                 | `/t/:slug/`(型定義一覧へリダイレクト) | `/t/:slug/`                           |
| コンテンツの一覧       | `/t/:slug/records/:typeKey`           | `/t/:slug/content/:typeKey`           |
| コンテンツの新規追加   | `/t/:slug/records/:typeKey/new`       | `/t/:slug/content/:typeKey/new`       |
| コンテンツの編集       | `/t/:slug/records/:typeKey/:recordId` | `/t/:slug/content/:typeKey/:recordId` |
| メディア               | `/t/:slug/assets`                     | `/t/:slug/media`                      |
| コンテンツタイプ(設定) | `/t/:slug/content-types`              | `/t/:slug/settings/content-types`     |
| モジュール(設定)       | `/t/:slug/modules`                    | `/t/:slug/settings/modules`           |

- API のパス(`/v1/t/:tenantId/records/...` など)と内部の型キーは変更しない(棚卸し 6.1 の決定どおり、変えるのは画面上の表示だけ)
- 管理画面の URL は利用者の目に入るため、表示の一部として扱う

## 7. 型が無いときの表示

- コンテンツタイプが 1 件も無い場合、「コンテンツ」見出しの下に案内を出す
  - owner: 「最初のコンテンツタイプを作成」(設定の型作成画面へのリンク)
  - editor / viewer: 「コンテンツの種類がまだありません。サイトの管理者に作成を依頼してください」

## 8. サイト選択画面(現テナント選択画面)

- 所属テナントが 1 件だけのときは、ログイン後にサイト選択を飛ばしてホームへ直接移る
- 複数のときは現在の選択画面を残し、ロール名を日本語(管理者 / 編集者 / 閲覧者)で表示する。slug の表示はやめる

## 9. 他の案との関係

- **案 B(ホーム / ダッシュボード)**: サイドバー中段の先頭の「ホーム」と `/t/:slug/` の着地点は案 B で設計する。案 A の実装時点で案 B が無ければ、暫定で最初のコンテンツタイプの一覧へリダイレクトする
- **案 E(型設計)**: 型の表示順を持たせると、サイドバーの並べ替えができるようになる
- **案 G(サイト設定とアカウント)**: 設定の「一般」「メンバー」と、アカウントメニューのプロフィール・パスワード変更
- **案 H(共通の表層)**: 切断時の共通バナー、パンくずの部品、見出しと主操作の配置
