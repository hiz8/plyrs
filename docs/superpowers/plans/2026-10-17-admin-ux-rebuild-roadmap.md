# 管理画面 UX 再構築 実装ロードマップ

> 出典: `docs/admin-ux/`(案 A〜H の設計書と [現状構造の棚卸し](../../admin-ux/current-structure.md))
> 本書はステップの分割と依存関係を固定する索引ドキュメントである。各ステップの着手時に、
> superpowers:writing-plans 形式の詳細計画(TDD・完全なコード付き)を本ディレクトリに 1 ファイルずつ作成する。

## 1. 進め方(2026-10-17 決定)

見た目は実装に入る前に Claude Design のキャンバス上で確定させる。そのため計画を 2 本に分ける。

| 系統                | 内容                                                                         | キャンバスとの関係                           |
| ------------------- | ---------------------------------------------------------------------------- | -------------------------------------------- |
| **T: 先行実装**     | API・メタモデル・URL・権限・状態管理など、見た目が変わっても作り直さない部分 | キャンバスを待たずに着手する                 |
| **D: キャンバス**   | トークンの値、共通部品、各画面の見た目と状態                                 | ローカルの Claude Code から `/design` で行う |
| **V: 見た目の実装** | トークン・部品・画面の組み立て                                               | 対応する D の確定後に着手する                |

V の順番は合意済みの「共通の土台(H)→ 骨格(A)→ 編集と一覧(C・D)→ ホーム・型設計・メディア・設定(B・E・F・G)」に従う。

キャンバスで決めた値と見た目は、各設計書(とくに [h-design-tokens.md](../../admin-ux/h-design-tokens.md))に書き戻してから V に入る。実装の根拠を設計書に一本化し、後から追えるようにするため。進め方の詳細は [デザイン依頼書](../../admin-ux/design-briefs/README.md) にまとめる。

## 2. 全体の流れ

```
T1〜T15(先行実装)  ───────────────────────────────────────────────►
D0 準備 → D1 デザインシステム → D2 骨格と主要 3 画面 → D3 残りの画面
              │                    │                    │
              ▼                    ▼                    ▼
           V1 (H)    ─►     V2 (A) → V3 (C・D)  ─►   V4 (B・E・F・G)
```

- D と T は並行して進められる。V は「対応する D の確定」と「必要な T の完了」の両方を待つ
- D2 は D1 の部品を、D3 は D2 の骨格を前提にする
